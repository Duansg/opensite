把浏览器窗口缩小，是检查响应式设计的开始，却不是终点。一个在手机上好用的网站，需要理解小屏幕上读者的任务与限制。

## 先决定什么最重要

桌面端可以让正文与侧栏同时出现。手机端的空间更有限，内容优先级就必须明确：标题、摘要与文章在前，作者介绍和标签索引在后。

导航也一样。常用入口应该容易找到，但不必始终占满屏幕。一个清楚的菜单按钮，比挤在同一行的小字更友好。

## 给手指留出空间

鼠标可以精准点击一个很小的目标，手指却不行。操作区域需要足够大，彼此之间也要有间隔。

按钮的视觉大小与可点击范围可以不同。一个二十像素的图标，可以放在四十四像素的按钮里，既保持轻盈，也便于触控。

```css
.icon-button {
  min-width: 44px;
  min-height: 44px;
  display: inline-flex;
  align-items: center;
  justify-content: center;
}
```

## 不让长内容撑破页面

代码块、表格和长链接，是最容易造成横向溢出的地方。代码可以在自己的区域滚动，图片要限制最大宽度，长链接则需要允许换行。

```css
.article {
  min-width: 0;
  overflow-wrap: anywhere;
}

.article pre {
  overflow-x: auto;
}

.article img {
  max-width: 100%;
  height: auto;
}
```

## 让动效懂得退场

悬停动画是桌面的附加体验，不应成为理解内容的前提。手机上没有悬停，启用「减少动态效果」的读者，也应该能完整阅读。

响应式设计最终关心的，是同一份内容在不同条件下仍然清晰可用。这比选择几个断点更重要。
