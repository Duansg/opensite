好用的工作流，往往不是从安装更多工具开始的。它更像是在每天重复经过的路径上，慢慢移走几块小石头。

## 让文件名回答问题

一个好的文件名应该让未来的自己少猜一次。比起 `final-v2-new.md`，用日期和主题组织记录，会更容易搜索和回溯。

```text
notes/
  2026-10-24-blog-search.md
  2026-10-25-reading-layout.md
  2026-10-26-deploy-checklist.md
```

不必把所有文件都纳入复杂的分类系统。只要命名保持稳定，全文搜索就能承担很多检索工作。

## 把重复命令变成一个入口

如果一个操作需要记住多条命令，就给它一个明确的名字。项目里的脚本是很适合的入口：它与代码一起版本管理，也能帮助新加入的人理解常用操作。

```json
{
  "scripts": {
    "dev": "astro dev",
    "build": "astro build",
    "check": "astro check"
  }
}
```

脚本名应该表达目的。让人先知道自己要做什么，再去了解它具体如何实现。

## 用一份笔记承接上下文

结束一天的工作前，花两分钟记下三件事：完成了什么，卡在哪里，下一步做什么。第二天回来时，你就不用重新从所有标签页里拼出昨天的思路。

这份笔记不用写成周报。几个短句，甚至一个错误信息和一个待验证的假设，就已经足够有用。

## 只优化真正重复的地方

不是每件事都需要自动化。一个每月只做一次、只花两分钟的任务，未必值得搭建完整系统。先观察，再决定是否投入。

当某个动作已经反复打断你，或者错误总发生在同一个位置，那里通常就是最值得改进的地方。
