互联网很大，但一个属于自己的地方，可以很小。一个标题，一篇文章，几个指向朋友的链接，就足够让一个想法有处安放。

这是一篇用于展示博客的示例文章。你可以保留它作为写作起点，也可以直接替换成自己的第一篇记录。

## 为什么还要写独立博客

在信息流里，一条内容的生命周期往往只有几小时。个人博客则允许我们用更长的时间尺度思考：今天写下的问题，可能在几个月后有了新的答案；两篇看似无关的笔记，也会慢慢长出连接。

> 写作不一定是为了证明自己知道什么，也可以是为了发现自己还没想清楚什么。

数字花园的有趣之处，是它不要求每篇内容都像最终定稿。一个正在生长的想法，也值得被记录。

## 把写作流程变得简单

越少的发布阻力，越容易让写作成为日常。这个博客把内容放在 Markdown 文件里：文章和代码一起管理，历史记录可以追溯，发布过程交给自动构建。

```text
写一篇 Markdown
       ↓
提交到 GitHub
       ↓
Cloudflare 自动构建
       ↓
新的文章出现在博客上
```

内容与样式分开，意味着写作者只需要关心段落、标题与链接。当你重新设计页面时，过去写下的东西仍然在那里。

### 给文章一个清晰的入口

每篇文章都包含标题、摘要、日期、分类与标签。摘要帮助读者决定是否继续，分类提供宽泛的方向，标签则让不同文章之间形成更细的联系。

```yaml
title: '一个值得留下的想法'
description: '用两句话告诉读者，这篇文章为什么值得读。'
date: 2026-11-04
category: 'thoughts'
tags: ['写作', '灵感']
```

## 设计是内容的一部分

一个博客不必长得像所有博客。蓝紫色背景、硬边框、像素插画与超粗标题，让这个空间有了自己的表情。但进入正文之后，视觉需要安静下来，把注意力交回文字。

这也是为什么首页与阅读页采用不同的节奏：首页负责邀请，文章页负责陪伴。它们共享同一套颜色和排版语言，却不承担同样的任务。

## 从一篇文章开始

不用在第一天就规划出完整的内容体系。先写一个你刚解决的问题，一次失败的尝试，或者一段让你停下来思考的话。

花园不会在一天里长成。只要持续留下真实的记录，它就会慢慢成为一个值得回来的地方。
